# MNIST Digit Recognizer — CNN from Scratch (PyTorch)

A convolutional neural network trained on MNIST, with an interactive Streamlit demo that lets you draw a digit and see the model predict it live, complete with a per-class confidence breakdown.

Built as a hands-on deep learning project — every layer's output shape was hand-derived before any code was written, following the CNN arithmetic (padding, stride, pooling, multi-channel filters) worked through from first principles.

## Results

**98%+ test accuracy** on the standard MNIST test set (10,000 held-out images).

## Architecture

```
Input (1×28×28)
  → Conv2d(1→8, kernel=3, padding=1) → ReLU → MaxPool2d(2,2)   →  8×14×14
  → Conv2d(8→16, kernel=3, padding=1) → ReLU → MaxPool2d(2,2)  → 16×7×7
  → Flatten                                                     → 784
  → Linear(784→64) → ReLU
  → Linear(64→10)                                                → 10 class logits
```

Trained with `CrossEntropyLoss` and the `Adam` optimizer (3 epochs, batch size 64).

## Usage

**1. Train the model** (downloads MNIST automatically on first run, saves weights when done):

```bash
python mnist.py
```

**2. Run the interactive demo:**

```bash
streamlit run demo.py
```

This opens a browser tab with a drawable canvas. Draw a digit (0–9) and the model will predict it live, showing a confidence bar chart across all 10 classes.

## Known limitations

The interactive demo revealed several real failure modes worth documenting honestly rather than hiding:

- **Stroke thickness mismatch.** The canvas initially used a much thicker stroke than MNIST's native digit style, and downscaling from 280×280 to 28×28 amplified this into blob-like shapes the model hadn't seen in training. Fixed by reducing `stroke_width` and using `Image.LANCZOS` resampling on resize, which produces smoother downscaling closer to MNIST's own preprocessing.
- **Distribution mismatch on invalid input.** An incomplete, ambiguous scribble (not a real digit) was classified with **100% confidence** as an "8" — a clear example of a model producing a confident answer for input it was never trained to handle, rather than expressing appropriate uncertainty.
- **Mouse-drawn geometry vs. natural handwriting.** Digits like "7" and "3" — which share some structural similarity (a top curve/stroke) — get lower, muddier confidence when drawn with a mouse, since mouse strokes tend to have sharper corners and straighter lines than natural pen strokes. MNIST's training data consists of real handwriting with natural curvature, so hand-drawn ambiguity between visually similar digits is more pronounced with mouse input than it would be with a scanned handwritten sample.

These aren't bugs in the model — they're a real, useful illustration of **train-serving skew**: the gap between the statistical distribution a model is trained on and the distribution it actually sees at inference time.

## What this project demonstrates

- CNN architecture design with fully hand-derived tensor shapes (convolution/pooling output-size arithmetic)
- Softmax and cross-entropy loss, understood from first principles
- Practical PyTorch patterns: `state_dict` saving/loading, `__name__ == "__main__"` guards for clean importable modules, `.eval()` mode
- Real debugging of a live demo, correctly diagnosing distribution mismatch between training data and live user input
